## Definition

**Terminance** — the governance discipline concerned with how an autonomous thing *ends its service*.

Retirement is not an operations cleanup task. It is a **governance event** with the same structure as admission:

- **Registry (LGD-I)** — the ending must be *registered*. A registry without a deregistration path is an incomplete registry.
- **Evidence (LGD-II)** — the ending must leave a *trace*: trigger basis, disposal record, migration record, shutdown event, lessons captured.
- **Gate (LGD-III)** — the ending must pass *gates*: trigger gate → approval gate → disposal gate → replacement-readiness gate → deregistration-confirmation gate.

The absence of these three produces **zombie systems** — models taken offline whose weights and data still run; devices withdrawn whose registration and UDI were never deregistered; facilities shut down with no disposal evidence.

## Why the term was coined

The descriptive English phrase *Retirement Governance* / *AI Decommissioning* is already a settled name in the literature — it belongs to others and cannot be claimed. The concept space, however, is a **structural gap**: existing frameworks (NIST AI RMF *Manage 4.1*, ISO/IEC 42001 *Govern 1.7*, Berkeley Agentic AI Profile) treat retirement as *one phase inside* the lifecycle, never as a governance object **equal in standing to admission**.

**Terminance** names that equal-standing position. The descriptive phrase stays as a search-facing subtitle; the coined term carries the claim.
